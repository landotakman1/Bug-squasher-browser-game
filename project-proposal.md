## Project Description

**What is it?**
Bug Squasher is a browser-based clicker game where players click on bugs to squash them and earn points. Players can use these points to purchase upgrades that help them squash bugs more efficiently by increasing their click power and auto-squash abilities. This game will run entirely within the browser with no installation required.

**Why does it matter?**
Bug Squasher provides a fun and engaging experience for players of all ages, encouraging strategic thinking and quick clicking as they aim to squash as many bugs as possible and bring the production server back online. This project combines two of my passions: game development and software engineering. I wanted to choose a project that is both fun and interesting to build while encouraging myself to further build upon my HTML and CSS skills while incorporating and learning JavaScript to create dynamic and interactive web experiences. Though perhaps less professionally ambitious than some other projects, it offers a unique opportunity to blend creativity with technical skill development as game design and development is a challenging pursuit that requires both creativity and technical proficiency.

**Who is it for?**
Bug Squasher is designed for casual gamers of all ages with a slight nod to programmers and tech enthusiasts who appreciate the humor and challenge of maintaining a production server while battling an onslaught of virtual bugs. Just as I was inspired by _suroi.io_, I hope to create a game that is both entertaining and inspiring to other budding developers who are looking to combine their love for gaming with their interest in technology.

## Feature Plan

### Project 01: (Week 05) - Working Prototype
These are the initial and essential features that make the game playable:

- A large clickable area that awards "points" each time it is clicked
- A live point counter that updates in real-time as points are earned
- At least three purchasable upgrades
- At least one upgrade that automatically squashes bugs over time
- Visual feedback when the player cannot afford an upgrade
- Clean layout and basic styling using HTML and CSS
- Game state that resets when the page is refreshed

### Project 02: (Week 06) - Final MVP
These features build upon the P01 foundation and aim to create a more complete and polished experience:

- Expanded upgrade list (ideally at least five upgrades with clearer progression)
- Improved visual feedback for upgrades and game events (button animations, color changes, etc.)
- Optional progress saving using local storage so player's state persists across page reloads
- Better game balance and clearer milestone progression for upgrades and achievements
- Light polish such as a few sound effects, pixel art bugs, or simple background music
- Responsive layout that works reasonably well on desktop and mobile

## Risks and Unknowns

**Risk 1 - JavaScript timing and state management:**
I have put quite a large amount of time into learning HTML and CSS via my coursework curriculum, freeCodeCamp, and Angela Yu's Udemy courses in addition to some past experience with Python and C#. However, I am still early in my JavaScript journey, and managing timing and state in a dynamic game environment may present challenges that are currently unknown to me. Extra time and study may be required to overcome these challenges.

**Risk 2 - Scope creep with upgrades and polish:**
I have learned through past game development cycles that it is VERY easy to get carried away with adding new features, upgrades, art, and music once the basic game loop is running. I will need to stay disciplined and adhere to the planned Project 01 feature list to make sure I have a playable version on time, and only expand carefuly going into Project 02.

**Risk 3 - Balancing the game:**
Making the upgrades and game loop feel rewarding without making the game too easy or too difficult can be challenging. I will need to carefully test and iterate on the game's balance to ensure a satisfying player experience.
